# 仮説と証拠を引き継ぐワークフロー

- 状態: ユーザーと合意した運用方針。実際の反映内容はGit差分で確認する。
- 対象・時点: 2026-11-05の相談とgrill。
- 用語: [CONTEXT.md](../../CONTEXT.md)。
- 運用手順: [hypothesis-and-evidence](../../skills/hypothesis-and-evidence/SKILL.md)。

## 目的

AIに設計・実装を広く任せながら、ユーザー自身の仮説と判断を明文化し、未知の問題を探す。検証条件を結果より先に決め、実際の証拠と未確認事項から評価する。

## 合意した進め方

1. 相談の段階で、ユーザーの既知の事実・仮説・AIの仮定を区別して明文化する。
2. 現行のgrillに、仮説への反論・盲点・プレモーテムの観点を追加する。
3. AIが設計案・選択肢・採用理由・トレードオフを提示し、ユーザーも質問しながら判断に参加する。
4. 仕様・Issueには、仮説、検討した内容、合意した仕様・設計、検証方針を残す。親Issueなどに記録があれば参照する。
5. Issue着手時に、何をもって検証済みとするかを実装前の条件として確認・確定する。
6. 実装後は、実際に行ったテストの内容と結果、スクリーンショット・ログ・トレースなどの証拠、未実施・未確認事項を提示する。
7. AI自身で「何か見落としていない？」と問い、元の目的・仕様・証拠に基づいた答えを示す。ユーザーに代わってAIが判断し、決めたことと理由も示す。

仮説は状況や理解に応じていつでも更新できる。以前の仮説と変更理由を残す。検証条件の変更が必要な場合も、元の条件・既に得た結果・変更理由を残し、結果を都合よく正当化しない。

## 既存ルールとの関係

今回の知見を既存ワークフローへ追加する。grillingの質問・分岐・確認のルール、to-specの網羅的なユーザーストーリーの指示は維持する。

質問範囲の絞り込み、読む量・生成量の最適化、変更量を理由とするIssueやPRの分割調整は今回扱わない。これらは今回の知見を取り入れた後に検討する。

## 組み込み先

| 追加先 | 担当する内容 |
| --- | --- |
| hypothesis-and-evidence | 仮説・検討・事前の検証条件・証拠・見落とし・AIの判断の共通手順 |
| grilling | 反論・盲点・プレモーテムの観点を既存の検討へ追加 |
| to-spec / to-tickets | 仮説・合意内容・事前の検証条件の記録と参照 |
| implement | 着手時の確認、実装後の証拠・未実施事項・AIの判断の提示 |
| review-standards | 見落としの再点検と回答 |
| Ugenのdocs/agents/issue-tracker.md | Issueへの記録と着手時の確認 |
| Ugenのdocs/agents/verification.md | 事前の検証条件・証拠・未確認事項・再点検の扱い |
| Ugenのdocs/agents/status-reporting.md | 結果・再点検の回答・AIの判断を報告へ含める指示 |
| UgenのAGENTS.md | 各skill・文書への案内 |

grill-with-docsはgrillingを呼ぶ現在の構成を引き継ぐ。共通ルールはskill、Ugen固有の検証完了条件はUgenのverification.md、個々の機能の仮説や判断はその機能のIssueなどに残す。
